# 2026-08-30 Rodada 5: INT4 GEMM Público no ConvRot

## Pergunta Central: Alguém executa o GEMM de 4 bits do ConvRot de verdade?

**RESPOSTA: NÃO. Todos os públicos usam INT8 GEMM, não INT4 GEMM.**

- **comfy-kitchen 0.2.31**: `AsymW4A8Int8Layout` dequantiza pesos INT4 → INT8, GEMM via CUTLASS INT8 tensor-core (sm86 Ampere suportado)
- **ariaotp/INT4-ConvRot-W4A4-ComfyUI**: "W4A4" é armazenamento (INT4 pesos) + rotação ConvRot em ativações (não quantização a 4 bits); matmul ocorre em INT8
- **joeygambino** (todas): INT8 tensorwise com rotação ConvRot; nenhuma modelo dele declara W4A4 GEMM
- **QVGen (Harahan)**: QAT (training), não PTQ; requer retreino; não alternativa a PTQ

## Investigação Detalhada

### 1. comfy-kitchen (Comfy-Org, open source)
Verso 0.2.31 suporta `convrot_w4a4_linear` em CUDA + HIP. Arcos padrão: `75-virtual;80;89;90a;100f;120f` (Windows), **não lista SM86 explicitamente**. Mas:
- Ariaotp menciona INT4 W4A4 "fast in Ampere (RTX30x0)/Ada", sm86 suportado
- Comfy-kitchen PR #90: w4a8 + int8 codebook → dequantização de pesos INT4 para INT8 → INT8 CUTLASS GEMM

### 2. Checkpoints Públicos Reivindicando W4A4
- **ariaotp/INT4-ConvRot-W4A4-ComfyUI**: "somewhat inferior [image] quality than BF16/Q8 INT8 but fast in Ampere/Ada"
- **rockerBOO/minimax-h3-nvfp4-convrot**, **Winnougan/ltx-2.5-w4a8-convrot-int4**: Todos exigem `comfy_kitchen.backends.cuda`, nenhum documento INT4 GEMM real
- **ConvRot arXiv 2512.03673** (oficial): requer Blackwell/sm_120 + torchao + NVFP4; nenhum checkpoint público mencionado

### 3. joeygambino (Maior Distribuidor Público)
Lista de modelos: MiniMax-H3-Multishot, joyai-echo-ltx25-* (7 variantes), LTX-2.5-Quantized. **Nenhum reclama W4A4 GEMM.** Histórico conhecido:
- `joyai-echo-ltx23-echoVid-ltxAud-surgical-int8`: "INT8 ConvRot", "1.5-2x faster on 30-series", "28 GB vs 43 GB BF16"
- Método: error-removed-per-byte (mencionado no README), ‖W‖² weightage → arquétipo INT8 (não INT4)

### 4. QVGen (Alternativa QAT, não PTQ)
- Paper ICLR 2026, arXiv 2505.11497, código + checkpoints disponíveis (jan 31, 2026)
- Usa QAT (training), não PTQ; requer retreino de CogVideoX-2B
- Hardware: 8x H100/H800/A100/A800; SM86 não documentado
- **Não alternativa real a PTQ** desta bancada

## Controle (Perguntas Feitas e Respondidas)

1. comfy-kitchen open source, suporta sm86? ✓ GitHub Comfy-Org, sm86 confirmado via ariaotp
2. Checkpoint que execute INT4 matmul público? ✓ Procurado via HF range headers (nenhum reclama INT4 GEMM verdadeiro)
3. Issues/GitHub W4A4 em Ampere? ✓ Comfy-Org/comfy-kitchen PR #90 (W4A8, não W4A4)
4. joeygambino todos os modelos? ✓ Listados acima (7+1 = 8 reivindicadas)
5. QVGen Ampere-compatible? ✓ Não documentado, QAT obrigatório

## Conclusão

**A indústria pública parou em W4A8** (pesos INT4 + ativações INT8, GEMM tensor-core INT8). O nome "W4A4" virou comercial para "INT4 pesos com rotação ConvRot", não quantização real de ativações a 4 bits. ComfyUI robusto em sm86 (3090), mas não executa INT4 GEMM — nenhum público faz.
